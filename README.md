# 알플레이 캔버스툴

알플레이 캔버스 제작에 필요한 캐릭터 설정, 프롬프트, 로어북, HTML 상태창·에셋, 변수, 업적, 업데이트 규칙과 캔버스 관리를 모은 전용 관리툴입니다.

작품 자료를 먼저 등록한 다음, 알플레이에서 내보낸 캔버스 JSON에 필요한 노드를 추가하고 연결합니다. 수정본 JSON을 다운로드해 알플레이에서 가져오는 흐름으로 사용합니다.

## 사용 순서

처음 사용한다면 **[실제 화면으로 따라하기](public/화면가이드.md)**를 보세요. 작품 추가부터 수정본 다운로드·검증까지 실제 화면 6개로 안내합니다. 프로그램 안에서는 **? → 화면으로 따라하기**로 열 수 있습니다.

**[클릭 안내 이미지 6장](public/guide/cards)**에는 버튼 위치와 설명이 함께 들어 있습니다. 이미지 파일만 저장해서 전달해도 되며, 프로그램의 가이드에서는 각 화면 아래 **설명 포함 이미지 저장**으로 받을 수 있습니다.

**[화면별 입력 항목 가이드](public/화면별가이드.md)**는 캐릭터 설정·작품 프롬프트·로어북·HTML 에셋·변수/규칙·업적·허브·캔버스·검증 화면에서 작성한 내용이 어느 노드에 반영되는지 설명합니다. 화면과 설명을 합친 이미지 10장도 함께 제공합니다. 각 화면의 **? → 입력 항목 → 캔버스 반영 안내**에서 해당 설명을 열 수 있습니다.

1. 아래 설치 명령으로 소스를 빌드하고 `실행.cmd`를 엽니다.
2. 오른쪽 위 **현재 작품 → 새 작품 추가**에서 작품을 만듭니다.
3. 캐릭터 설정·로어북·프롬프트·HTML 에셋을 등록하고 저장합니다.
4. 허브를 사용한다면 상단 **허브 관리**에서 대상과 스토리의 연결 구성을 저장합니다.
5. **알플레이 캔버스 → 콘텐츠 편집**에서 기준 캔버스 JSON을 불러옵니다.
6. 각 탭의 체크리스트로 노드를 추가하고, 마지막 허브 관리 탭에서 허브를 연결합니다.
7. **수정본 다운로드**로 받은 JSON을 알플레이에 가져옵니다.

## 실행

- `실행.cmd`: 서버를 켜고 브라우저를 엽니다.
- `종료.cmd`: 실행기로 켠 서버를 종료합니다.
- `데이터 폴더 변경.cmd`: 연결할 외부 데이터 폴더를 선택합니다.

기본 주소는 `http://127.0.0.1:4174`입니다. 기존 관리툴과 다른 포트를 사용합니다. Node.js가 필요하며, 작품 MD 내보내기는 Python 3.9 이상이 필요합니다. `PYTHON_EXECUTABLE`로 Python 경로를 지정할 수 있습니다.

이 저장소는 **소스 배포본**입니다. GitHub에서 받은 ZIP은 설치 없이 실행되는 포터블 버전이 아닙니다. 처음 한 번 Node.js 설치, 라이브러리 설치, 화면 빌드가 필요합니다. AI는 필수가 아니며, 설치가 어렵다면 아래 **AI에게 설치·오류 해결을 요청하기**의 양식을 README와 함께 전달하세요.

### 1. 실행 환경 준비

- **Node.js 22 이상:** [공식 다운로드](https://nodejs.org/en/download)에서 Windows용 LTS 설치 파일로 설치합니다. 설치가 끝나면 열려 있던 터미널을 닫고 새로 엽니다.
- **pnpm 10:** 이 프로젝트의 기존 설치 환경은 `10.15.1`입니다. 아래 명령은 같은 버전을 설치합니다. [pnpm 공식 설치 안내](https://pnpm.io/installation)도 참고할 수 있습니다.
- **Git:** `git clone`으로 받을 때만 필요합니다. ZIP 다운로드에는 필요하지 않습니다.
- **Python 3.9 이상:** 작품 전체 MD 내보내기를 사용할 때만 추가로 필요합니다. 기본 편집과 캔버스 JSON 작업에는 필요하지 않습니다.

아래 명령은 Windows **명령 프롬프트(cmd)** 기준입니다. 한 줄씩 실행하고, 오류가 나오면 다음 단계로 넘어가기 전에 오류를 확인하세요. 설치·빌드 때는 인터넷 연결이 필요합니다.

```bat
node --version
npm --version
npm install -g pnpm@10.15.1
pnpm --version
```

`node --version`은 `v22` 이상, `pnpm --version`은 `10.15.1`이 표시되면 됩니다.

### 2. 프로그램 받기

**ZIP으로 받는 경우:** [GitHub 저장소](https://github.com/gurumstudio9/Rplay-tool)에서 **Code → Download ZIP**을 누르고 압축을 모두 풉니다. 압축 파일 안에서 바로 실행하지 마세요. `package.json`과 `실행.cmd`가 함께 보이는 폴더를 탐색기로 연 뒤, 주소창에 `cmd`를 입력하고 Enter를 누르면 그 폴더에서 명령 프롬프트가 열립니다. 폴더 이름은 `Rplay-tool-main` 등으로 표시될 수 있습니다.

**Git으로 받는 경우:** Git을 설치한 뒤, 프로그램을 둘 상위 폴더에서 다음 명령을 실행합니다.

```bat
git clone https://github.com/gurumstudio9/Rplay-tool.git
cd Rplay-tool
```

### 3. 처음 한 번 설치·빌드

ZIP과 Git 모두 `package.json`이 있는 폴더에서 실행합니다.

```bat
pnpm install --frozen-lockfile
pnpm build
```

첫 명령은 필요한 라이브러리를 `node_modules/`에 설치하고, 두 번째 명령은 화면을 `dist/`에 만듭니다. 두 명령이 오류 없이 끝나고 `dist/index.html`이 생겼으면 준비가 끝났습니다.

### 4. 실행·종료

이후에는 `실행.cmd`를 더블클릭합니다. 브라우저에서 작품 선택 화면이 열리면 정상입니다. 브라우저가 자동으로 열리지 않으면 서버 실행 성공 메시지를 확인한 뒤 `http://127.0.0.1:4174`를 직접 엽니다. 브라우저 탭을 닫아도 서버는 계속 실행되므로 종료할 때는 `종료.cmd`를 사용합니다.

매번 설치·빌드할 필요는 없습니다. 소스를 업데이트했을 때 다시 설치·빌드합니다. `node_modules`, 빌드 결과 `dist`, Node.js·Python 실행 환경과 작품 데이터는 저장소에 포함하지 않습니다.

## 코드와 데이터

```text
작업폴더/
├─ Rplay-tool/               # 독립 실행하는 알플레이 캔버스툴
├─ data/                     # 이 도구의 작품 자료: 최초 실행 시 자동 생성
└─ rplay-canvas-settings.json # 데이터 경로를 바꿨을 때 저장되는 개인 설정
```

작품 데이터는 기본적으로 `../data/works/<작품ID>/알플레이/`에 저장합니다. 데이터 파일을 복사하거나 이동하지 않으며, 관리툴 내부에 `data/`를 만들지 않습니다. 기존 이미지·다른 플랫폼 관리 기능은 포함하지 않습니다. 가져온 캔버스에 이미 들어 있는 노드는 유지합니다.

경로 우선순위는 실행 환경의 `CHARACTER_MANAGER_DATA_DIR` → `../rplay-canvas-settings.json`의 `dataDirectory` → 기본 `../data`입니다. 상대경로는 코드 폴더 기준입니다. 서버는 선택한 데이터 폴더의 `.env`를 읽고 Python에도 같은 데이터 경로를 전달합니다. 화면에서 데이터 폴더를 바꾸면 다음 서버 실행부터 적용됩니다.

로그는 데이터 폴더의 `logs/rplay-canvas.stdout.log`와 `rplay-canvas.stderr.log`, 실행 정보는 `../.rplay-canvas-runtime.json`에 저장합니다. 기존 관리툴의 개인 설정과 실행 정보를 따로 사용합니다.

이 저장소는 도구 코드만 관리합니다. `data/`는 일반 폴더로 사용할 수 있으며 Git 설정은 필요하지 않습니다. 캔버스툴 소스 저장소는 [gurumstudio9/Rplay-tool](https://github.com/gurumstudio9/Rplay-tool)입니다.

### DATA가 없는 첫 실행

- 데이터 경로를 따로 설정하지 않았으면 도구 폴더 옆에 `data/`를 자동으로 만듭니다. 빈 JSON을 수동으로 준비할 필요가 없습니다.
- 처음에는 **기본** 작품이 표시됩니다. **현재 작품 → 새 작품 추가**에서 이름을 입력하고 **작품 추가**를 누릅니다.
- 작품을 만들면 `data/works.json`과 `data/works/<작품ID>/알플레이/` 아래의 `characters/`, `lorebook/`, `prompts.json`, `variables.json`, `hubs.json`을 초기화합니다. 다른 자료는 해당 기능에서 저장할 때 생성됩니다.
- 기존 데이터가 있다면 **데이터 폴더 변경.cmd** 또는 화면 오른쪽 **데이터 폴더**에서 연결하고 서버를 다시 실행합니다.
- 별도로 지정한 데이터 폴더가 없어졌으면 오류를 표시합니다. 기존 폴더를 다시 연결하거나 화면에서 기본 경로로 복귀한 다음 재시작합니다. 서버가 시작되지 않으면 `데이터 폴더 변경.cmd`로 존재하는 외부 폴더를 선택합니다.

### 메뉴별 역할

처음 사용한다면 화면 오른쪽 관리 영역의 **처음 사용 가이드** 또는 [사용 가이드 문서](public/사용가이드.md)를 확인하세요. 주요 메뉴와 기능 옆의 **?** 버튼에서 용도·사용 순서·저장 방법을 볼 수 있으며, 도움말 창에서 전체 가이드를 내려받을 수 있습니다.

| 메뉴 | 작업 |
| --- | --- |
| 캐릭터 설정 | 인물 이름·그룹·중요 정보·상세 설명 관리 |
| 작품 프롬프트 | 공통 메인, 시작·일반 노드, 전체 스토리 및 관련 규칙 관리 |
| 로어북 | 분류·제목·호출 키워드·본문 관리 |
| HTML 에셋 | 상태창 HTML 작성과 미리보기 |
| 허브 관리 | 독립된 허브 데이터와 IN·OUT 연결 대상 관리 |
| 알플레이 캔버스 | 등록 자료를 캔버스에 적용하고 수정본 다운로드 |

## 프롬프트 노드

| 종류 | 편집 항목 |
| --- | --- |
| 시작 노드 | 메인 프롬프트, 에디셔널, 전체 스토리, 시작 가이드, 시작 메시지 |
| 일반 노드 | 메인 프롬프트, 에디셔널, 전체 스토리 |

각 노드의 **메인 + 에디셔널**로 적용합니다. 메인은 작품 공통으로 공유하고, 에디셔널과 전체 스토리는 노드마다 따로 저장합니다. 노드 설정에서 종류를 변경할 수 있습니다. 일반 노드를 캔버스에 적용할 때는 시작 가이드·시작 메시지를 비웁니다.

기존 데이터는 첫 노드 또는 시작 내용이 있는 노드를 시작 노드로 읽고, 공통 전체 스토리를 노드 배경의 초기값으로 사용합니다. 읽기만으로 데이터 형식을 바꾸지 않습니다. 기존 추가 프롬프트는 추가 프롬프트 탭에서 그대로 편집하며, 빈 노드에도 새로 작성할 수 있습니다.

`prompts.json`에는 노드 종류와 메타데이터를, `prompts/<노드ID>/worldStory.md`에는 각 노드의 배경을 저장합니다. 기존 관리툴과 같은 작품을 번갈아 편집할 때는 다른 화면의 오래된 편집 내용을 저장하지 않도록 먼저 새로고침합니다.

## 허브 데이터 관리

상단 **허브 관리**에서 작품별 허브 원본을 관리합니다. 캔버스 파일을 불러오지 않아도 사용할 수 있습니다.

허브를 추가·선택한 뒤 IN 모드에서 대상 타입과 로어북 분류를 고르고 체크합니다. **현재 목록 전체 선택**은 현재 필터·검색에 표시된 대상에만 적용되며, 다른 타입과 다른 허브의 선택은 유지합니다. 개별 체크를 해제하면 그 항목만 제외됩니다. OUT 모드에서는 같은 왼쪽 목록에서 연결할 시작·일반 스토리를 선택합니다.

**저장**을 누르면 `../data/works/<작품ID>/알플레이/hubs.json`에 허브 이름과 대상 참조를 저장합니다. 로어북·인물·스토리 본문을 복사하지 않습니다. 업데이트 규칙은 저장 파일명으로 참조하며, 원본이 삭제되거나 파일명이 바뀌어도 기존 참조를 자동 삭제하지 않고 목록에 표시합니다.

## 캔버스 관리

캔버스를 불러와 콘텐츠 비교·적용, 내보내기 전후 누락 검사를 할 수 있습니다. 캐릭터 추가 시 감정·성·특수용 빈 이미지 노드 3개와 인물 연결선을 자동 생성합니다.

콘텐츠 편집기 마지막 **허브 관리** 탭에서 저장된 허브를 선택하고 **허브 추가**로 허브 노드를 넣습니다. 로어북·인물·업데이트 규칙은 각 기존 탭에서 추가합니다. 마지막에 **허브 연결**을 누르면 저장된 설정에 따라 기존 대상 → 허브 → 스토리를 연결합니다. 같은 연결은 중복 추가하지 않으며, 대상이 없거나 이름이 중복되면 해당 항목을 표시합니다. 수정 결과는 **수정본 다운로드**로 받습니다.

모든 콘텐츠 탭의 **추가·삭제 대상** 체크리스트에서 누락 노드 추가와 레거시 삭제를 개별 선택하거나 일괄 적용할 수 있습니다. 타입 필터와 전체 선택은 현재 표시된 항목에만 적용됩니다. 인물은 후보 그룹도 포함하고, 상태창은 HTML 에셋, 스토리는 등록된 시작·일반 프롬프트를 기준으로 누락을 찾습니다. 중복 항목은 확인 대상으로 남깁니다. 레거시는 등록 원본과 매칭되지 않는 캔버스 노드이며, 삭제 결과는 편집 되돌리기로 복원할 수 있습니다.

### 체크리스트 사용 예

로어북 타입을 **지역**으로 고른 뒤 **현재 목록 전체 선택**을 누릅니다. 제외할 항목의 체크를 풀고 **선택 추가**를 누르면 나머지 지역 로어북만 추가됩니다. 다른 타입의 선택은 필터를 바꿔도 유지되며, 작업은 현재 표시된 타입에만 적용됩니다.

| 상태·버튼 | 의미 |
| --- | --- |
| 누락 · 추가 가능 | 등록된 원본은 있고 캔버스 노드는 없음 |
| 누락 모두 추가 | 현재 필터의 누락 노드를 모두 추가 |
| 레거시 · 원본 없음 | 캔버스 노드와 매칭되는 등록 원본이 없음 |
| 선택 레거시 삭제 / 레거시 모두 삭제 | 선택한 범위의 노드와 연결선을 캔버스 수정본에서 제거 |
| 중복 확인 필요 | 이름 등이 겹쳐 안전하게 구분할 수 없어 일괄 작업 제외 |
| 원본으로 갱신 | 이미 있는 노드의 내용을 저장된 원본으로 갱신 |
| 편집 되돌리기 | 불러왔던 기준 캔버스 상태로 복원 |

캔버스 편집은 메모리의 수정본에 적용합니다. 마지막에 **수정본 다운로드**를 눌러야 결과 파일을 받을 수 있습니다. 기준 JSON과 작품 원본 파일을 덮어쓰지 않습니다.

### 두 허브 관리 화면의 차이

- **상단 허브 관리:** 작품의 허브 원본을 만들고 로어북·인물·규칙과 스토리를 체크해 저장합니다.
- **캔버스 편집기의 마지막 허브 관리 탭:** 저장된 허브를 캔버스에 추가하고, 실제 캔버스 노드끼리 연결합니다.

**허브 연결**에서 대상이 없다고 표시되면 먼저 해당 탭에서 누락 노드를 추가합니다. 원본 허브 구성을 수정했다면 저장 후 **저장된 허브 새로고침**을 누릅니다. 추가 순서는 자유롭고, 연결을 마지막에 하면 됩니다.

### 검증과 내보내기

- **왕복 검증:** 알플레이로 가져가기 전 JSON과 다시 내보낸 JSON을 비교해 본문 잘림·누락을 확인합니다.
- **노드 분석:** 가져온 캔버스의 노드 구성을 확인합니다.

작품 전체 MD 내보내기에는 공통 메인, 각 노드의 전체 스토리와 시작 내용, 로어북, 캐릭터 본문이 포함됩니다. 직접 실행할 때는 `python assemble_work.py 작품ID --platform 알플레이`를 사용합니다.

## 저장·백업·개인 정보

- 작품 내용과 연결 설정은 도구 옆 `data/`에 저장합니다. 백업할 때는 연결 중인 `data/` 폴더를 복사합니다.
- 데이터 폴더 경로는 `rplay-canvas-settings.json`, 실행 정보는 `.rplay-canvas-runtime.json`, 로그는 연결한 데이터 폴더의 `logs/`에 저장합니다.
- 최근 선택한 작품 등 화면 상태는 브라우저의 로컬 저장소에도 남을 수 있습니다.
- 저장소에는 작품 데이터, 개인 설정, `.env`, 로그, 개인 작업 문서 및 개발용 AI 메모를 포함하지 않습니다. HTML 미리보기 기본값은 일반 예시입니다.
- 도구를 다른 사람에게 전달할 때는 저장소의 소스나 별도로 만든 배포본을 사용합니다. 개인 `data/`와 설정 파일은 공유할 자료인지 확인해 별도로 전달합니다.

## 자주 생기는 문제

| 증상 | 확인할 내용 |
| --- | --- |
| Node.js runtime not found / node 또는 npm을 찾을 수 없음 | Node.js 22 이상을 설치한 뒤 터미널을 새로 열고 `node --version`, `npm --version`을 확인합니다. 계속 실패하면 `where node`, `where npm` 결과를 확인합니다. |
| pnpm을 찾을 수 없음 | `npm install -g pnpm@10.15.1`을 실행하고 터미널을 새로 엽니다. `pnpm --version`과 `where pnpm`으로 확인합니다. |
| PowerShell에서 npm.ps1 또는 pnpm.ps1 실행이 차단됨 | 위 안내대로 명령 프롬프트(cmd)를 열어 실행합니다. PowerShell에서는 `npm.cmd`, `pnpm.cmd`로 실행할 수도 있습니다. |
| package.json이 없다는 오류 / ERR_PNPM_NO_PKG_MANIFEST | 현재 위치가 소스 폴더인지 확인합니다. `package.json`과 `실행.cmd`가 함께 있는 폴더에서 명령을 실행합니다. |
| Cannot find module 'dotenv' 등 라이브러리를 찾지 못함 | 소스 폴더에서 `pnpm install --frozen-lockfile`을 실행합니다. 다른 PC의 `node_modules`를 복사하는 대신 이 PC에서 설치합니다. |
| ERR_PNPM_OUTDATED_LOCKFILE 또는 잠금 파일 호환 오류 | `pnpm --version`을 확인하고 안내한 버전을 사용합니다. `package.json`과 `pnpm-lock.yaml`을 같은 배포 버전에서 받았는지 확인합니다. 해결되지 않으면 두 파일과 오류를 함께 전달해 진단받습니다. |
| 설치 중 다운로드·인증서·네트워크 오류 | 인터넷 연결과 오류에 나온 주소를 확인합니다. 오류 전문을 전달해 진단받고, 인증서 검증을 끄는 방법으로 우회하지 않습니다. |
| 빌드된 화면이 없습니다 | 소스 폴더에서 `pnpm install --frozen-lockfile`, `pnpm build`를 실행합니다. 성공 후 `dist/index.html`이 있는지 확인합니다. |
| pnpm build에서 TypeScript·Vite 오류 | 첫 오류부터 마지막까지 복사하고 Node.js·pnpm 버전과 함께 전달합니다. 빌드가 실패한 상태에서는 이전 화면이 남거나 실행되지 않을 수 있습니다. |
| 창이 닫히거나 서버 준비를 확인하지 못함 | 명령 프롬프트에서 `실행.cmd`를 실행해 오류를 확인합니다. 서버 시작 단계의 오류는 연결한 데이터 폴더의 `logs/rplay-canvas.stderr.log`도 확인합니다. |
| 4174 포트 사용 중 / 같은 포트에서 다른 관리툴이 실행 중 | 기존에 실행한 도구의 `종료.cmd`를 사용합니다. `pnpm start`나 `pnpm dev`로 켰다면 해당 터미널에서 Ctrl+C로 종료합니다. 어떤 프로그램인지 모르면 `netstat -ano \| findstr :4174` 결과의 LISTENING 행에 있는 PID를 확인하고 진단받습니다. |
| 브라우저에서 연결할 수 없음 | 먼저 `실행.cmd`의 성공 여부와 서버 로그를 확인합니다. 기본 주소는 `http://127.0.0.1:4174`이며, `PORT`를 따로 지정했다면 실행기에 표시된 주소를 사용합니다. |
| 선택한 데이터 폴더가 없습니다 / 코드 폴더 밖이어야 합니다 | `데이터 폴더 변경.cmd`로 실제 존재하는 외부 데이터 폴더를 선택합니다. 환경변수 `CHARACTER_MANAGER_DATA_DIR`가 지정되어 있으면 그 값이 개인 설정보다 우선합니다. |
| 개인 설정 파일을 읽을 수 없습니다 | 오류에 표시된 `rplay-canvas-settings.json`의 JSON 형식을 확인합니다. 원본을 백업한 뒤 `dataDirectory` 값과 문법을 점검하고, 작품 데이터 폴더는 삭제하지 않습니다. |
| 작품이나 허브 목록이 비어 있음 | 현재 작품과 연결한 데이터 폴더를 확인하고, 원본 관리 화면에서 저장했는지 확인합니다. |
| 허브 연결 버튼을 누를 수 없음 | 허브·입력 대상·스토리 노드가 모두 있는지, 중복 이름이 없는지 확인합니다. |
| DATA 경로를 변경했는데 그대로임 | `종료.cmd`로 종료한 후 `실행.cmd`로 다시 실행합니다. |
| Python 실행 파일을 찾지 못했습니다 / MD 내보내기 실패 | `python --version`으로 3.9 이상인지 확인합니다. 명령이 없거나 Microsoft Store만 열리면 설치한 Python의 실행 경로를 확인합니다. 다른 Python을 지정하는 방법은 아래를 참고합니다. |

Python이 설치되어 있지만 자동으로 찾지 못한다면, 명령 프롬프트에서 `set "PYTHON_EXECUTABLE=C:\실제 Python 설치 폴더\python.exe"`로 실제 파일 경로를 지정한 뒤 **같은 창에서** `실행.cmd`를 실행합니다. 기존 서버는 먼저 종료해야 합니다. 이 설정은 해당 창에만 적용됩니다. Python이 정상 실행되는데도 실패하면 화면의 오류나 Python traceback을 확인합니다.


| 문제 단계 | AI에게 추가로 전달할 자료 |
| --- | --- |
| 설치·빌드 | `package.json`, `pnpm-lock.yaml`, 실패한 명령의 출력 |

로그는 **현재 연결한 데이터 폴더**의 `logs/rplay-canvas.stdout.log`와 `logs/rplay-canvas.stderr.log`에 있습니다. 서버가 시작되기 전 실패했다면 로그 파일이 없을 수 있으므로 실행 창의 오류를 전달합니다. 공유할 때는 관련 오류 부분만 보내고 `.env`, 실행 정보의 토큰, 비공개 작품 내용은 제외하세요. 로컬 전용 `docs/`, `AGENTS.md`, `GEMINI.md` 없이도 이 README와 `public/`의 사용 가이드로 안내할 수 있습니다.

### 업데이트

작성 중인 자료를 저장하고 연결 중인 외부 `data/`를 백업한 뒤 서버를 종료합니다.

- **Git으로 받은 경우:** 소스 폴더에서 `git pull` → `pnpm install --frozen-lockfile` → `pnpm build` 순서로 실행합니다. `git pull`에서 로컬 변경 충돌이 나오면 오류와 `git status` 결과를 확인하고, 변경을 버리는 명령을 임의로 실행하지 않습니다.
- **ZIP으로 받은 경우:** 최신 ZIP을 새 폴더에 압축 해제하고 설치·빌드를 다시 실행합니다. `git pull`은 사용할 수 없습니다. 새 폴더가 이전과 다른 상위 위치라면 `데이터 폴더 변경.cmd`로 기존 외부 데이터 폴더를 연결합니다. 소스 ZIP에는 기존 작품 데이터가 들어 있지 않습니다.

다시 `실행.cmd`를 열고 기존 작품 목록이 표시되는지 확인합니다.

## 개발

의존성은 `pnpm-lock.yaml`로 관리합니다.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm start
```

`pnpm build`는 TypeScript 검사와 화면 빌드를 함께 실행합니다. 수정 후에는 다시 빌드하고 서버를 재시작합니다. Vite 개발 서버 포트는 5174이며 API 요청을 4174로 전달합니다. 배포 시에는 코드·빌드·실행 의존성만 포함하고 작품 데이터와 개인 설정은 제외합니다.
